# Інтеграція `@filbert/runtime`

Покроково, під Phaser-проєкт на Vite. Написано проти справжнього коду
`monsters-wheels` (гілка `store/crazygames`), тож шляхи й імена — не приклади,
а те, що там реально лежить.

Читати згори вниз. Кроки 1–3 дають працюючий потік подій; кроки 4–6 роблять
дані придатними для аналізу; крок 7 — чекліст перед релізом.

---

## 0. Що ви отримуєте і чого це коштує

Гра починає звітувати нам сесії, покази реклами й прогрес. Дані — технічні:
**без cookie, без крос-сайтових ідентифікаторів, без персональних даних**.

Витрата на боці гри — одна точка ініціалізації й по одному рядку на кожен
наявний журнал реклами. Рефакторити монетизацію **не потрібно** (див. крок 5).

---

## 1. Підключення пакета

Поки пакет живе підтекою `sdk/` у репозиторії платформи, тож підключення —
копією:

```bash
cp -r webgames-platform/sdk  monsters-wheels/src/vendor/runtime
```

```ts
import { start } from "./vendor/runtime/src/index.js";
import { attachPhaser } from "./vendor/runtime/src/phaser.js";
```

Vite збирає TypeScript із вашого `src/` сам, тож окремий крок збірки пакета не
потрібен.

> **Чому не git-залежність.** npm не вміє надійно тягнути **підтеку**
> репозиторію (`path:`-синтаксис — це pnpm/yarn, не npm). Щойно пакет виїде в
> окремий приватний репозиторій — а це заплановано до К4 — підключення стане
> звичайним `"@filbert/runtime": "github:Long-as-Python/<repo>#v1.0.0"`, і
> копію можна буде викинути.

## 2. Найменша робоча інтеграція

Одна точка, якнайраніше — у `src/main.ts`, **до** створення `Phaser.Game`:

```ts
import { start } from "@filbert/runtime";

export const fg = start({
  game: "monsters-wheels-2",        // канонічний слаг реєстру
  build: __BUILD_VERSION__,          // крок 3
  endpoint: "https://webgames.filbert.games",
});
```

> **`game` — це слаг з реєстру, не назва теки і не заголовок.**
> Для Monsters Wheels це `monsters-wheels-2` — та сама гра на нашому хості й на
> GameDistribution має **один** ідентифікатор, інакше статистика по платформах
> розпадеться на дві незв'язані гри. Старий слаг `monster-wheel` теж приймається
> (він зареєстрований як аліас) і мовчки зводиться до канонічного.

Усе. З цієї миті йдуть сесії, `env` і heartbeat.

## 3. `build` — обов'язковий, і його не вгадують

`build_zip.sh -v 1.7.67` знає версію, але **в бандл вона не потрапляє**: у
`vite.config.ts` немає жодного `define`, а `package.json` тримає `0.0.0`.
Без цього кроку кожна сесія звітує `build: "unknown"`.

Ми свідомо не вигадуємо версію: **неправильна мітка гірша за чесне
`unknown`** — вона тихо приписує числа одного білда іншому, і на дашборді це
нічим не викрити.

**У `vite.config.ts`:**

```ts
export default defineConfig({
  define: {
    __BUILD_VERSION__: JSON.stringify(process.env.VITE_BUILD_VERSION ?? "dev"),
  },
  // ...
});
```

**У `src/vite-env.d.ts`:**

```ts
declare const __BUILD_VERSION__: string;
```

**У `scripts/build_zip.sh`** — версія вже є у змінній `version`, лишається її
експортувати перед викликом збірки:

```bash
export VITE_BUILD_VERSION="$version"
```

> Поруч уже є доведений приклад того самого прийому: `swVersionPlugin()`
> (`vite.config.ts:601`) штампує білд, підставляючи `__SW_VERSION__` у
> `build/sw.js`. Різниця лише в тому, що нам потрібне значення в бандлі гри, а
> не в service worker'і, і семантична версія замість `Date.now()`.

## 4. Адаптер Phaser

Дає три числа, за якими портали судять гру, без ручного інструментування:

```ts
import { attachPhaser } from "@filbert/runtime/phaser";

const game = new Phaser.Game(config);
attachPhaser(fg, game);
```

Що він міряє сам:

| Поле | Що це |
|---|---|
| `ttfr` | час до першого відмальованого кадру (`postrender`, не `ready`) |
| `tload` | час до завершення сцени завантаження |
| `tplay` | час до першої ігрової сцени |
| `bytes` | байти, завантажені до цього моменту |

`bytes` і `tplay` — це рівно те, чим **CrazyGames міряє гру** на Basic Launch,
і те, що ми раніше рахували руками.

**Ключі сцен.** За замовчуванням завантажувальними вважаються ключі, що містять
`boot`/`preload`/`loading`/`load`, ігровими — `game`/`play`/`race`/`level`.
У Monsters Wheels це збігається (`PreloadScene`, `GameScene`), але якщо
іменування інше — вкажіть явно:

```ts
attachPhaser(fg, game, {
  loadingScenes: ["Zavantazhennia"],
  gameplayScenes: ["Perehony"],
});
```

Якщо не збіглось нічого, `boot` усе одно піде через 20 секунд — краще неточне
число, ніж жодного.

Опції: `trackScenes` (подія на кожен перехід сцени, типово `true`),
`fpsSampleMs` (семпл частоти кадрів, типово 30000, `0` вимикає).

## 5. Адаптер Defold

Defold не дає об'єкта гри, який можна передати в адаптер, тож форма інша: на
сторінці лежить місток, а Lua кличе його через `html5.run` — єдиний канал, який
у Lua до сторінки є.

**На сторінці.** Defold не має бандлера — є згенерований `index.html` і тека
файлів поруч. Тому в пакеті є **один зібраний файл**: покладіть
`dist/filbert.browser.js` поруч із `index.html` і додайте в шаблон:

```html
<script src="filbert.browser.js"></script>
<script>
  var fg = Filbert.start({ game: "car-eats-car-2-deluxe", build: "0.28" });
  Filbert.attachDefold(fg);
</script>
```

Скрипт визначає `window.Filbert` із `start`, `attachDefold`, `attachPhaser` і
константами версії. Дебаг-канал сам нічого не відкриває, доки в адресі гри
немає `?devsdk=1` — тож той самий файл спокійно їде на портал.

Якщо бандлер усе ж є:

```ts
import { attachDefold } from "@filbert/runtime/defold";

attachDefold(fg);
```

**У грі** — покласти `defold/filbert.lua` з пакета у проєкт і покликати
в кількох місцях:

```lua
local filbert = require("filbert.filbert")

filbert.ready()             -- рушій піднявся, наш код виконується
filbert.loading_finished()  -- перший екран видно й можна торкатись
filbert.gameplay_start()    -- почалась гра
filbert.phase("level_3")    -- будь-яка своя віха
```

### Що він бачить сам

| Що | Звідки |
|---|---|
| `ready` | `Module.onRuntimeInitialized` |
| `load_25` … `load_100` | прогрес завантажувача Defold |
| який `.wasm` приїхав, скільки важив, чи `pthread` | resource timing |
| `crossOriginIsolated` | сторінка |

Рядок про рушій окупає адаптер сам собою. Бандл везе **дві** збірки wasm
приблизно по 6 МБ, а качається рівно одна — і яка саме, залежить від
cross-origin isolation. Тобто це заодно перевірка, що COOP/COEP на дев-хості
справді спрацювали: без них панель міряла б однопотокову збірку, вважаючи, що
міряє ту, що їде на портал.

### Чого він НЕ вгадує, і це навмисно

`loading_finished` **не виводиться з прогресу завантажувача**. Лоадер каже
«ассети скачано», а метрика означає «гравець бачить перший екран і може його
торкнутись». На живому 0.21 мережа закінчилась на 13 секунді, а смуга
завантаження через дві хвилини показувала 24 % — між цими двома подіями
хвилини. Автоматично прирівняти їх означало б збрехати рівно в тому місці,
заради якого все й робиться. Каже гра.

### Канал команд

`filbert.take_command()` віддає рядок, який панель поклала ззовні, і **одразу
його стирає** — інакше команда виконувалась би щоразу, поки панель не перезапише
поле, а вона цього робити не зобов'язана.

### Міграція зі старого `perf.lua`

Адаптер підбирає мітки з наявного `window.__cec2d_perf`, тож збірка починає
звітувати ще до того, як перейде на новий місток. Вимикається опцією
`adoptLegacyMarks: false`.

Одна відмінність, яку варто знати: старий `perf.lua` склеював назву мітки прямо
в JS-літерал без екранування, тож апостроф або зворотний слеш у назві ламали
вираз і мітка зникала мовчки. Місток у пакеті екранує.

## 6. Реклама — по рядку на кожен журнал

У проєкті **три незалежні буфери** `adLog` у двох різних формах:

| Файл | Форма |
|---|---|
| `src/monetization/crazyGames.ts:129` | `{name, type, outcome, ms, detail?}` |
| `src/monetization/gameDistribution.ts:58` | те саме |
| `src/monetization/adPlacement.ts:120` | `{t, name, type, outcome, ms, status?}` |

**Зводити їх до однієї форми не треба.** `ad()` приймає обидві: `detail` і
`status` означають те саме й зводяться до одного поля, час проставляється сам,
якщо його не передали. Це навмисно — інакше інтеграція перетворилася б на
рефакторинг монетизації.

У кожному з трьох файлів, поруч із наявним `adLog.push(entry)`:

```ts
adLog.push(entry);
fg.ad(entry);        // ← весь рядок інтеграції
```

Найцінніший із трьох — `adPlacement.ts`: це і є воронка плейсментів
(`requested → started → completed → failed`) з кодом причини, заради якої все
затівалось.

Ім'я мережі можна задати один раз у конфігу: `provider: "crazygames"`.

## 7. Прогрес

```ts
fg.level(levelId, "start");
fg.level(levelId, "win",  { ms: elapsed, score: stars });
fg.level(levelId, "fail", { ms: elapsed });
fg.level(levelId, "revive");
fg.level(levelId, "x2");

fg.buy("engine-upgrade", 250, "coins");
```

`PlayerProgress` (`src/config/garage/PlayerProgress.ts`) уже тримає монети,
зірки, медалі, машини й апгрейди — точки виклику ставляться там, де ці значення
змінюються.

Потрібна метрика, якої ще немає в схемі:

```ts
fg.custom("tutorial-skipped");
fg.custom("garage", { opened: "car_3" });
```

`custom` існує, щоб **нова метрика не чекала на реліз пакета**. Схему легше
розширити, ніж почистити.

## 8. Вимикач і чекліст релізу

### `VITE_TELEMETRY=off` має викидати код побайтово

Білд, який ми віддаємо замовнику або в стор, мусить уміти бути **чистим**: без
коду телеметрії й без згадки нашого домена. У CrazyGames у Basic requirements
прямим текстом стоїть *«No external ads»*, у GameDistribution — заборона на
сторонні рекламні рішення; наш запит рекламним не є, але невідомий вихідний
домен на QA — це привід для питання.

Механізм у проєкті вже доведений: `VITE_SHIPPING` і `crazyGamesSdkTagPlugin()`
саме так викидають чужі SDK.

```ts
// src/telemetry.ts
import type { Client } from "@filbert/runtime";

const OFF = import.meta.env.VITE_TELEMETRY === "off";

export const fg: Client = OFF
  ? (new Proxy({}, { get: () => () => {} }) as Client)
  : (await import("./telemetry.on")).fg;
```

Ключове: **динамічний `import()` за статично обчислюваною умовою** — Vite
викидає гілку цілком, разом із рядком домена.

### Чекліст перед кожним релізом

```bash
# 1. збірка без телеметрії не містить нашого домена
VITE_TELEMETRY=off npm run build
! grep -r "webgames.filbert.games" dist/ && echo "OK: чисто"

# 2. звичайна збірка містить версію, а не 'dev'
npm run build && grep -o "1\.7\.[0-9]*" dist/assets/*.js | head -1
```

Перший рядок варто додати в `build_zip.sh` — він ловить регресію назавжди.

### Що сказати замовнику

> Студія збирає технічну телеметрію власних ігор: тривалість сесій, покази
> реклами, проходження рівнів. Персональні дані не збираються, cookie не
> використовуються, крос-сайтових ідентифікаторів немає. За потреби телеметрія
> вимикається однією змінною збірки, і в такому білді її код відсутній повністю.

**Сказати це самим, до того як замовник знайде.** Виявити невідомий вихідний
запит самостійно — гірше в сто разів, ніж почути про нього від нас.

## 9. Перевірка, що воно працює

**У консолі гри:**

```js
__fgS()
// { sid, iid, game, build, plat, plats, plath, url, seq, queued, lost }
```

Дивитись на `build` (не має бути `unknown`) і `plat` (не має бути `unknown`
там, де ви знаєте платформу).

**На боці сервера:** `/_admin/probe` шле справжні батчі тим самим шляхом і
показує лічильники сховища. Якщо probe пише події, а гра — ні, проблема в
інтеграції, а не в приймачі.

**Мережа:** один `POST /api/s/monsters-wheels-2` раз на ~12 секунд, відповідь
завжди `204` з порожнім тілом. **`204` — це норма, а не помилка.**

### Якщо подій немає

| Симптом | Причина |
|---|---|
| Запиту немає в мережі взагалі | Блокувальник. Перевірте в приватному вікні без розширень |
| `build: "unknown"` | Крок 3 не зроблено |
| `plat: "unknown"` | Хост не в реєстрі — скажіть нам, це один рядок на сервері |
| Запит є, подій на дашборді немає | Слаг не збігається з реєстром — перевірте `game` |

## 10. Чого воно ніколи не зробить

- **Не зронить гру.** Кожен метод ковтає власні помилки; якщо клієнт не
  сконструювався — повертається клієнт із порожніми методами, а не виняток.
  Нічого не `await`'иться в шляху старту. Порожня чи помилкова відповідь
  сервера — нормальний результат.
- **Не завантажить нічого ззовні.** Жодних сторонніх скриптів, жодного CDN.
- **Не надішле подій на кадр.** Черга обмежена 100 подіями / 64 КБ; найстаріші
  відкидаються, а втрата повідомляється полем `drop`, а не ховається.

Перевірити останнє твердження можна прямо: підніміть приймач, що віддає `500`,
і переконайтесь, що гра стартує як завжди.
